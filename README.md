# Yoten — новостная лента

Агрегатор: RSS 63 изданий → пересказ на русском → одна карточка на новость, сколько бы изданий о ней ни писали → треды для продолжающихся историй. Лента одной колонкой в духе редакторских журналов.

Продакшен: сайт на Vercel (`dub1` в `vercel.json`), база Supabase Postgres с pgvector, сбор в GitHub Actions. В конфиге — 63 издания и 70 RSS-фидов. Локальный справочник `../issues.md` содержит историю проверок изданий и статистику за 19–26 октября, а не текущий статус доступности.

Документация сверена с кодом 6 ноября 2026. Проверки саммари и уведомления добавлены в коммите `37df2f8`; факт отправки кода в `main` не подтверждает успешную обработку конкретной статьи на проде. Диагностика и действия при сбоях — в [инструкции по эксплуатации](docs/operations.md).

## Быстрый старт

```bash
npm ci                 # Node.js 24, как в GitHub Actions
cp .env.example .env    # заполнить переменные из таблицы ниже
npm run db:init         # схема БД и издания из конфига
npm run fetch           # собрать новости за последние сутки
npm run dev             # http://localhost:3000
```

### Переменные окружения

| Переменная | Где | Что |
|---|---|---|
| `DATABASE_URL` | сайт, сбор | Postgres с pgvector |
| `RP_ORIGIN` | сайт | адрес сайта для ссылок в превью |
| `SESSION_SECRET` | сайт | проверка старых кук входа — до 24 января 2027 (см. `src/lib/viewer.ts`) |
| `THREADS_VIEW` | сайт | `1` — лента с тредами (включено на проде; на preview-выкладках всегда) |
| `GEMINI_API_KEYS` | сбор | ключи Google AI Studio через запятую, у каждого своя бесплатная квота |
| `GEMINI_MODELS` | сбор | модели через запятую, в порядке перебора |
| `GROQ_API_KEY` | сбор | запасная модель |
| `GROQ_MODEL` | сбор | модель Groq; значение по умолчанию задаётся в `src/lib/groq.ts` |
| `MIN_DETAIL_CONTEXT_LENGTH` | сбор | минимум символов исходного текста для генерации «Читать» (600) |
| `TELEGRAM_BOT_TOKEN` | сбор, отчёт | токен бота для окончательных ошибок саммари и ежедневного отчёта |
| `TELEGRAM_CHAT_ID` | сбор, отчёт | чат получателя уведомлений |
| `RETENTION_DAYS` | сбор | сколько дней хранить статьи (7) |
| `DEDUPE_THRESHOLD` | сбор | порог склейки по тексту (0.75) |

Для ручных прогонов: `FETCH_SOURCES="Dezeen,Esquire"` — только эти издания, `FETCH_SINCE_DAYS=1` — окно на сутки шире, `FETCH_LIMIT=N` — не больше N статей, `THREADS_SHADOW=0` — без раскладки по тредам.

После первого прогона с диагностикой сбор автоматически проверяет неизвестные ссылки за последние 72 часа, чтобы подхватывать запоздалые элементы RSS. Внутри каждого фида сначала идут статьи за последние сутки; догрузка ограничена 10 попытками на издание (суммарно для всех его фидов) и 50 на прогон. Лимиты применяются и к неудачным попыткам, чтобы не расходовать квоту на бесконечные повторы. Уже известные и окончательно отклонённые ссылки пропускаются. Ручной `FETCH_SINCE_DAYS` сохраняет прежнее поведение и не ограничивается бюджетом автоматической догрузки. Для Fast Company исходные ISO-даты без зоны явно трактуются как UTC через `feedDateOffset` в конфиге.

Каждый обработанный фид оставляет строку `SOURCE_DIAGNOSTIC` в логе: HTTP-статус, тип ответа, возраст CDN-кэша, SHA-256 RSS, свежесть элементов, число известных/сохранённых/отложенных ссылок, причины исключения и ошибки. При аномалии сохраняется снимок до 10 элементов с заголовками, ссылками, исходными датами и решениями — без полного текста RSS или дополнительных запросов к изданию. В GitHub запись содержит `workflowRunId`. Диагностика сохраняется одной пачкой за прогон в `source_fetch_diagnostics`; суточные счётчики по Москве — в `source_volume_daily`. Обе истории живут 56 дней независимо от очистки статей. Новые таблицы создаются `db:init` или автоматически при первом сборе из `db/fetch-diagnostics.sql`; ошибка диагностики выводится в лог и не останавливает сбор.

## Сбор (`src/jobs/fetchAndProcess.ts`)

Основной запуск настроен через внешний cron-job.org каждые 30 минут с вызовом `workflow_dispatch` у `.github/workflows/fetch-cron.yml`. Внешнее расписание не хранится в репозитории. Запасное расписание workflow: в минуту 7 ежечасно с 07 до 22 часов по Москве и в 23:07, 02:07, 05:07. Ограничение длительности джобы — 60 минут; фактическое время зависит от числа статей и ответов моделей.

1. **Ленты.** Все RSS качаются сразу, по 8 параллельно; обход каждый прогон начинается с другого издания. Свежие статьи за 24 часа идут первыми; после появления предыдущей диагностики неизвестные ссылки догружаются в пределах 72 часов с бюджетом 10 на издание и 50 на прогон. Отсекаются реклама (`src/lib/adFilter.ts` и правила издания), лайв-блоги и виды материалов, заданные в конфиге издания (`src/config/sources.ts`).
2. **Текст и фото** (`src/lib/ogTags.ts`). Текст — селектор издания, JSON-LD или абзацы страницы; у части изданий — сразу из RSS. Галерея — по правилам `GALLERY_SITES` для движка издания. Страницы NYT, WSJ и Bloomberg закрыты всегда и не запрашиваются; если страница закрыта, карточка строится по RSS.
3. **Эмбеддинги** (`src/lib/embeddings.ts`) — локально, `Xenova/all-MiniLM-L6-v2`: вектор заголовка с текстом и отдельно заголовка. Считаются от оригинала: пересказ стирает различия между похожими новостями.
4. **Склейка** (`src/lib/grouping.ts`). Статья сравнивается с первыми статьями карточек за 24 часа: первые 12 часов — по тексту или заголовку, дальше — только другие издания и строже. Запасные правила: парный материал издания, одновременные новости, общее имя в заголовке, одна и та же обложка.
5. **Пересказ** (`src/lib/summarizer.ts`, промпты — `src/lib/prompt.ts`). Один ответ содержит главное, продолжение под «Читать» (при контексте от 600 символов) и до двух тем. Контекст: текст страницы → описание → RSS, переход к следующему при `NO_CONTENT`. Проверки качества могут вызвать повтор, общий бюджет — 4 попытки. Спорт и `shopping` в ленту не идут. Для статьи в готовом кластере генерация обычно не нужна; исключение — у кластера нет «Читать», а новая статья содержит достаточно текста.
6. **Показ.** Статьи прогона появляются в ленте одной пачкой (`visible_at`); статьи старше `RETENTION_DAYS` удаляются вместе с карточкой.
7. **Треды** (`src/lib/threads.ts`). Новые карточки сравниваются с карточками за 72 часа (похожий заголовок или редкое имя в пересказе); модель решает, продолжение ли это той же истории, и пишет, что нового. Тред — одно событие и его прямые последствия, не больше 6 карточек; похожие треды модель сверяет и сливает. Ручные решения «не в этот тред» хранятся в `thread_exclusions`.

**Модели.** Gemini (`src/lib/gemini.ts`) перебирает пары модель+ключ; последняя удачная пара запоминается в `.gemini-state.json`. Если все варианты перегружены — минута паузы и повтор Gemini, затем при повторной неудаче переключение на Groq на 3 минуты. При исчерпании квот Gemini переход на Groq происходит без минутной паузы. Размер квот определяется аккаунтом и моделью, не этим README. Если исчерпаны оба провайдера, прогон останавливается.

**Отчёт о состоянии** (`src/jobs/healthReport.ts`, DIS-81) — каждый день в Telegram: его отправляет первый прогон сбора после 10:00 по Москве (шаг в `fetch-cron.yml`, метка в кэше — раз в сутки; расписание GitHub пропускало запуски), вручную — `health-report.yml` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` в секретах GitHub). Ошибки сбора, RSS и обработки проверяются за последние сутки; объём статей, обложки, галереи и «Читать» — за предыдущий полный день по Москве. Для объёма используются два и более предыдущих таких же дня недели либо минимум три сопоставимых будних/выходных дня; пока истории недостаточно, отчёт это указывает. Отсутствие свежих публикаций в RSS само по себе не считается технической ошибкой: такие наблюдения перечисляются отдельно. Повторный отказ RSS, пустой фид, нераспознанные даты и сбой обработки различаются. Длинный отчёт разделяется на сообщения по границам строк. `--dry` не отправляет Telegram-сообщения и не изменяет БД.

## Сайт (`app/`)

- **Лента** — `app/page.tsx`, `FeedList.tsx`, `FeedCard.tsx`; данные — `src/lib/feed.ts`, JSON — `GET /api/feed`. Рубрики, вкладки «Новые» и «Прочитанные», плашка «N Новых», открытие с места, где читатель остановился. Карточка становится прочитанной через 2,5 секунды на экране.
- **Треды** — одна позиция ленты: первая карточка, общая галерея и посты с новыми подробностями; карточка без новых подробностей уходит в «Также пишут». Повторы фото отсекаются по отпечаткам (`src/lib/imageHash.ts`).
- **Пост** — `/post/<номер статьи>` с превью для мессенджеров.
- **Издание** — `/source/<слаг>` (DIS-80): все карточки, где есть его статья, без вкладок и тредов; открывается по иконке издания в карточке.
- **Мобильная шапка** при прокрутке вниз уезжает, при прокрутке вверх возвращается вместе с вкладками (`--chrome-offset`, `MobileChrome.tsx`).
- **Как приложение на телефоне:** манифест (`app/manifest.ts`) — с экрана «Домой» открывается на весь экран; `viewport-fit=cover` и отступы `env(safe-area-inset-*)`; цвет статус-бара по теме (`theme-color`, `theme.ts`); без серой вспышки при тапе, `:hover` только при мыши, отклик на нажатие и запрет выделения у кнопок (`globals.css`).
- **Картинки** — через `/api/image-proxy` (только адреса из базы, до 15 МБ); если прокси не справился, браузер грузит напрямую.
- **Без регистрации** (DIS-65). Посетитель — браузер: `middleware.ts` выдаёт куку `yoten_browser` со случайным номером на 400 дней, прочитанное и выключенные издания хранятся в базе под его хешем (`src/lib/viewer.ts`). Строка в `users` заводится при первой отметке или переключателе; браузеры, не заходившие год, удаляются при сборе.
- **Настройки** — издания (`/settings`), тема и размер текста (`/settings/display`).

## Контроль качества саммари

После окончательной неудачи исправления бот отправляет отдельное Telegram-уведомление в конце запуска сбора: издание, заголовок, ссылка, причины и число попыток. Промежуточные отказы и успешно исправленные ответы не уведомляют. Очередь `summary_quality_alerts` создаётся автоматически; ссылка уникальна, отправленные записи хранятся 56 дней. Недоставленные сообщения сохраняются и повторяются не раньше чем через 30 минут, максимум 10 сообщений за запуск. Таймаут запроса — 5 секунд, новые отправки прекращаются через 10 секунд от начала цикла; время ожидания БД отдельно не ограничено. Сбой Telegram не запускает генерацию заново. Как и для обычного отчёта, нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; workflow передаёт их шагу сбора. При аварии между доставкой и отметкой в БД возможен повтор сообщения.

Перед сохранением `src/lib/summaryQuality.ts` проверяет основной текст и продолжение: минимум 4 буквенных слова и 20 букв, завершённую пунктуацию, язык, служебную разметку и явные ответы модели вместо пересказа. При отсутствии `===` проверяется каждый абзац. Язык отклоняется при 3 и более буквах из списка нерусских кириллических букв или доле кириллицы ниже 30% в части от 20 букв. Проверка идёт до подрезания предложений. Точный сигнал `NO_CONTENT` переключает источник контекста; пустой текст после строки темы считается дефектом ответа. Gemini собирает все текстовые части ответа без внутренних рассуждений; пустой ответ и статус завершения, отличный от `STOP`/`stop`, отклоняются.

Общий бюджет — 4 попытки генерации на статью, включая смену контекста; последняя использует Groq при наличии ключа. Это бюджет качества: существующие ограниченные транспортные повторы при сетевых сбоях считаются отдельно. После исчерпания бюджета ссылка записывается в `skipped_links` с причиной `summary_quality` минимум на 7 дней (обычное окно автоматического сбора — 72 часа). Повторная ручная обработка более старых статей после очистки списка возможна. Если статья дополняет существующий кластер, сохраняется прежнее саммари кластера.

`SUMMARY_REJECTED` фиксирует причины отклонения каждой попытки, `SUMMARY_FAILED` — ссылку, источник, число попыток, причины и принятое действие. В `source_fetch_diagnostics.data.summaryFailures` сохраняются первые 50 неудач на источник за запуск на 56 дней; полный список остаётся в логах запуска. Счётчик `summaryErrors` учитывает эти сбои. Сетевые ошибки и квоты не помечают статью как дефектную. Проверки структуры и языка не заменяют сверку фактов с оригиналом.

## Ограничения

- Защита изданий не обходится: закрытые страницы дают только доступный текст RSS, иногда полный, иногда анонс.
- Эмбеддинги английские: статьи на других языках не склеятся с английскими.
- Прочитанное и настройки живут в одном браузере: другое устройство, другой браузер или очистка данных сайта — с нуля.
- Пропускная способность сбора упирается в бесплатные квоты Gemini и Groq.
