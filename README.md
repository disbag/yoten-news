# Yoten — новостная лента

Агрегатор новостей: RSS 50 изданий → пересказ на русском (главное + продолжение
под катом «Читать») → темы → склейка одинаковых новостей разных изданий в одну
карточку. Фронтенд — лента карточек одной колонкой на Next.js в духе
редакторских изданий вроде Kinfolk.

Продакшен: Vercel (функции в регионе `dub1`, рядом с базой), база — Supabase
Postgres с pgvector (`eu-west-1`), сбор — GitHub Actions.

## Возможности

- **50 изданий** — от NYT и BBC до IGN, Dezeen и Car and Driver; у части изданий
  несколько лент-разделов (The Guardian: мир, искусство и дизайн, книги,
  путешествия; BBC: мир, культура, путешествия). Полный список — `src/config/sources.ts`, состояние каждого
  издания — `../issues.md`.
- **Пересказ на русском** — главное (2–3 предложения) в карточке и продолжение
  под катом «Читать», дописанное к главному без повторов. Оба — пересказ своими
  словами, не перевод. У изданий, которые отдают только анонс (NYT, WSJ,
  Bloomberg), продолжения нет: модель домысливала бы.
- **Темы** — технологии, наука, культура, кино и сериалы, музыка, дизайн, игры,
  авто, путешествия, экономика, политика, происшествия, здоровье, другое; до
  двух тем на статью. Спорт и шопинг модель помечает, и такие статьи в ленту не
  попадают.
- **Склейка** — одна новость от нескольких изданий (или повторно от одного) —
  одна карточка с «+N источника» и списком «Также пишут».
- **Галереи** — у изданий, где у статьи несколько фото, карточка показывает
  карусель; на весь экран — с увеличением двумя пальцами.
- **Страница поста** `/post/<номер>` и кнопка «Поделиться» — с превью ссылки в
  мессенджерах (издание, текст, фото главного издания).
- **Вкладки «Новые» и «Прочитанные»**, выбор изданий, тема (светлая, тёмная,
  как в системе) и размер текста — в настройках.
- **Защита от выдумывания фактов** — модели запрещено добавлять детали, которых
  нет в исходном тексте; при малом материале она сокращает ответ.

## Быстрый старт

```bash
npm install
cp .env.example .env    # DATABASE_URL, GEMINI_API_KEYS, SESSION_SECRET …
npm run db:init         # схема БД и источники из конфига
npm run fetch           # собрать новости за последние сутки
npm run dev             # http://localhost:3000
```

### Переменные окружения

| Переменная | Где | Что |
|---|---|---|
| `DATABASE_URL` | сайт, сбор | Postgres с pgvector (Supabase, Neon) |
| `GEMINI_API_KEYS` | сбор | ключи Google AI Studio через запятую — у каждого проекта своя бесплатная квота |
| `GEMINI_MODELS` | сбор | модели через запятую, перебираются по порядку |
| `GROQ_API_KEY` | сбор | запасной провайдер, см. ниже |
| `RETENTION_DAYS` | сбор | сколько дней хранить статьи (7) |
| `DEDUPE_THRESHOLD` | сбор | порог склейки по тексту (0.75) |
| `SESSION_SECRET` | сайт | подпись куки сессии |
| `RP_ID`, `RP_ORIGIN` | сайт | домен и адрес сайта для входа по ключу (passkey); `RP_ORIGIN` же — адрес в превью ссылок |

Для ручных прогонов: `FETCH_SOURCES="Dezeen,Esquire"` — только эти издания,
`FETCH_SINCE_DAYS=1` — окно ещё на сутки назад, `FETCH_LIMIT` — не больше
N статей.

### Модели: Gemini и запасной Groq

Ключ Google AI Studio — [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
Бесплатная квота считается на проект и модель, поэтому при исчерпанной квоте
(429) `src/lib/gemini.ts` перебирает ключи на той же модели, потом переходит к
следующей. При перегрузке модели у Google (5xx или нет ответа за 30 секунд)
переходит к другой модели, а если не отвечает и она — пробует ещё по одному
ключу на перегруженных моделях. Каждая пара модель+ключ — не больше раза за
запрос; «квота исчерпана» — только если все неудачи были 429. Последнюю удачную
пару запоминает между прогонами (`.gemini-state.json`, в Actions — через кеш).

Когда Gemini исчерпан везде, сбор на 3 минуты переключается на
[Groq](https://console.groq.com/keys) (`src/lib/groq.ts`). Если это перегрузка,
а не квота, сначала ждёт минуту и пробует Gemini ещё раз: у Groq небольшой
суточный лимит (200 тыс. токенов). Groq же — последняя
попытка, если Gemini несколько раз ответил не на русском. Кончились оба —
прогон останавливается, следующий начнёт снова с Gemini.

## Сбор новостей (`src/jobs/fetchAndProcess.ts`)

Для каждого издания — его RSS (и дополнительные ленты-разделы, `extraFeeds`).
Каждый прогон начинает обход с другого издания. Берутся статьи за последние
24 часа, ещё не обработанные (по ссылке), кроме:

- рекламы и подборок со скидками — общий фильтр `src/lib/adFilter.ts` плюс свои
  правила издания (`adTitlePattern`, `adLinkPattern`);
- лишних видов материалов издания — `skipLinkPattern` (записи эфиров и подкасты
  Bloomberg), `skipTitlePattern` (выпуски подкастов 9to5Mac), `skipCategoryPattern`
  (рассылки и оплаченные материалы);
- лайв-блогов и ежедневной карикатуры New Yorker.

Дальше по шагам:

1. **Текст и фото статьи** (`src/lib/ogTags.ts`). Текст: свой селектор издания
   (`contentSelector`) → JSON-LD `articleBody` → абзацы самого большого
   `<article>` → абзацы по странице. Если издание отдаёт статью целиком в RSS —
   берётся оттуда (`preferFeedContent`). Фото: обложка — `og:image` или картинка
   из фида; галерея — по правилам `GALLERY_SITES` для движка издания (селекторы
   кадров, приведение адресов к одному размеру, со страницы или из RSS).
   Страницы NYT, WSJ, Bloomberg, Dezeen, Abduzeedo и ещё нескольких изданий
   закрыты для бота — остаётся то, что есть в фиде.
2. **Эмбеддинги** (`src/lib/embeddings.ts`, `@huggingface/transformers`, модель
   `Xenova/all-MiniLM-L6-v2` в сжатом виде q8, локально, без API) — два вектора:
   заголовок + текст статьи и отдельно заголовок. Считаются от оригинала, а не от
   пересказа: пересказ стирает различия между похожими новостями.
3. **Склейка** (`src/lib/grouping.ts`). Новая статья сравнивается только с
   «якорями» — первыми статьями карточек — моложе 24 часов:
   - первые 12 часов — мягкие правила (текст ≥ 0.75, или 0.65 при одном анонсе;
     заголовок ≥ 0.80; заголовок ≥ 0.70 вместе с текстом ≥ 0.58);
   - с 12 до 24 часов — только статьи других изданий и по строгому правилу с
     опорой на заголовок;
   - дополнительные правила: парный материал того же издания (обзор и его
     фотогалерея), одновременные новости разных изданий, совпадение с уже
     приклеенной статьёй, пара имён в заголовке, одна и та же картинка.
4. **Пересказ** (`src/lib/summarizer.ts`, промпты — `src/lib/prompt.ts`). Один
   запрос к модели: главное, продолжение и темы. Контекст — текст статьи, при
   его отсутствии `og:description`, затем анонс из RSS. Статья, приклеенная к
   существующей карточке, к модели не идёт: у карточки текст уже есть (кроме
   случая, когда карточка начиналась с анонса, а у новой статьи полный текст).
5. **Показ.** Статьи прогона скрыты до его конца и появляются в ленте одной
   пачкой (`visible_at`). В конце — удаление статей старше `RETENTION_DAYS`
   (карточка уходит целиком, вместе с отметками о прочитанном).
6. **Треды** (`src/lib/threads.ts`, DIS-36). После показа пачки новые карточки
   раскладываются по тредам — продолжениям одной истории. Кандидаты — карточки
   последних 72 часов с похожим заголовком (старше суток — только очень похожие),
   а если таких меньше трёх — карточки с тем же редким именем в пересказе;
   до трёх тредов; решение и «что нового» даёт один запрос к модели. Тред, в
   который добавилась карточка, сверяется с похожими тредами, и те, что модель
   считает той же историей, сливаются. Гайды («How to…», «walkthrough») в треды
   не берутся. Для фото тредов считаются
   отпечатки (`src/lib/imageHash.ts`, dHash через `sharp`), чтобы одно фото у
   разных изданий не повторялось в галерее. Ошибка раскладки не роняет прогон;
   `THREADS_SHADOW=0` отключает шаг.

### Расписание

`npm run fetch` запускается в GitHub Actions (`.github/workflows/fetch-cron.yml`).
Основной запуск — внешний: [cron-job.org](https://cron-job.org) каждые 30 минут
вызывает `workflow_dispatch` через API GitHub. Расписание `schedule` в самом
workflow — запасное (днём раз в час, ночью раз в 3 часа): если оно совпадает с
основным запуском, прогоны встают в очередь друг за другом. Прогон идёт 1–15
минут.

## Сайт

Next.js App Router (`app/`):

- **Лента** (`app/page.tsx`, `app/components/FeedList.tsx`, `FeedCard.tsx`) —
  карточки по дате самой свежей статьи, рубрики, вкладки «Новые» / «Прочитанные»
  у вошедших. Карточка раскрывается на месте по «Читать» или «+N источника».
  Подгрузка вниз и вверх, открытие с места, где читатель остановился, плашка
  «N Новых» по новым статьям. Прочитанной карточка становится, пробыв на экране
  2,5 секунды.
- **Данные** — `src/lib/feed.ts` в два шага: сначала отбираются нужные карточки,
  потом для них собираются тексты, источники и картинки. Тот же код отдаёт JSON
  по `GET /api/feed`. Обложка и галерея карточки — с одной статьи: с галереей,
  если она есть хоть у одной, иначе фото главного издания.
- **Страница поста** — `app/post/[id]/page.tsx`: один пост целиком и теги превью
  (`og:*`). Номер в адресе — номер статьи; если её карточку позже склеили с
  другой, ссылка откроет объединённую.
- **Треды** — на рабочем сайте с 18 октября 2026 (переменная `THREADS_VIEW=1`
  в Vercel для production), на тестовых выкладках (`VERCEL_ENV=preview`) всегда,
  локально — с `THREADS_VIEW=1`. Без переменной лента идёт карточками, как
  раньше (после новой выкладки). Тред — одна позиция ленты: первая карточка целиком, общая
  галерея и посты с новыми подробностями; карточка без новых подробностей
  склеивается с первой («Также пишут»).
- **Картинки** — через `/api/image-proxy`: часть изданий не отдаёт фото чужому
  сайту. Прокси пускает только адреса из базы, с таймаутом 15 секунд и пределом
  15 МБ. Если прокси не справился (Telegraph не отдаёт фото серверам Vercel),
  браузер загружает картинку напрямую.
- **Вход** — по ключу (passkey, `@simplewebauthn`) или регистрация по email;
  сессия — подписанная кука. **Настройки** — `/settings` (издания) и
  `/settings/display` (тема и размер текста, хранятся в браузере).

Оформление: кремовый фон, антиква Lora, гротеск Onest для текста новости,
акцент — терракотовый `#C94F3D` (цвет логотипа); есть тёмная тема.

## Скрипты

| Команда | Назначение |
|---|---|
| `npm run fetch` | Собрать и обработать новости за последние сутки |
| `npm run feed` | Вывести ленту в консоль |
| `npm run dev` / `build` / `start` | Сайт |
| `npm run db:init` | Применить схему БД и добавить источники из конфига |
| `npm run backfill-og` | Досчитать картинку и текст для уже собранных статей |
| `npm run backfill-categories` | Досчитать темы для статей без них |
| `npm run resummarize` | Пересчитать пересказы (например, после правки промпта) |
| `npm run upgrade-quality` | Пересчитать пересказы с полным текстом вместо анонса |
| `npm run threads` | Разложить по тредам непроверенные карточки (`THREADS_SINCE_HOURS`, по умолчанию 24) |
| `npm run favicons` | Скачать иконки новых изданий в `public/favicons` (`-- --force` — все заново) |

## Известные ограничения

- Обход защиты изданий сознательно не делается: закрытые для бота страницы дают
  только анонс из RSS.
- Индекс `ivfflat`/`hnsw` на эмбеддингах не используется: при хранении в неделю
  точный перебор и надёжнее, и достаточно быстр.
- Бесплатные квоты Gemini и Groq — основной потолок пропускной способности сбора.
