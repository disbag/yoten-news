# news-feed-mvp

Пайплайн: RSS → AI-саммари → локальный embedding → дедупликация по кластерам,
плюс минимальный фронтенд на Next.js (лента карточек + разворот по клику со
списком источников). Без авторизации — личный инструмент для проверки идеи.

## Установка

```bash
npm install
cp .env.example .env
```

### 1. Постгрес с pgvector

Проще всего через [Neon](https://neon.tech) или [Supabase](https://supabase.com) — оба бесплатны для старта.

- Создай проект.
- В SQL-редакторе выполни `CREATE EXTENSION IF NOT EXISTS vector;` (или это сделает `npm run db:init`, если расширение доступно на твоём тарифе).
- Скопируй connection string в `.env` → `DATABASE_URL`.

### 2. Саммаризация: Gemini

- Ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey) → `.env` → `GEMINI_API_KEY`.
- Модель — `.env` → `GEMINI_MODEL` (по умолчанию в коде — `gemini-flash-lite-latest`).
- Бесплатный тариф ограничен на уровне конкретной модели (напр. 500 запросов/сутки) — при
  `RESOURCE_EXHAUSTED` (см. `describeQuotaError` в `src/lib/gemini.ts`) можно переключиться на
  другую модель в Google AI Studio через `GEMINI_MODEL` (у каждой модели свой лимит), а не ждать
  сброса. Раньше был второй провайдер (OpenRouter) как раз для такого случая — убрали: и
  бесплатные модели на OpenRouter либо сами оказывались проксёй в тот же Google AI Studio
  free-tier (см. `gemma-*:free`, упирается в тот же лимит), либо были "thinking"-моделями,
  тратящими весь `max_tokens` на скрытые рассуждения вместо ответа.

### 3. Инициализация БД

```bash
npm run db:init
```

Применит схему (`db/schema.sql`) и добавит источники из `src/config/sources.ts`.

### 4. Запуск пайплайна

```bash
npm run fetch
```

Пройдётся по всем источникам, для каждой новой статьи сделает саммари и embedding,
попробует склеить с похожей свежей новостью (источник может быть любым, включая тот же самый).

### 5. Посмотреть ленту

```bash
npm run feed
```

Выведет в консоль готовую ленту, сгруппированную по кластерам (одинаковым новостям).

### 6. Фронтенд

```bash
npm run dev
```

Откроет Next.js на [localhost:3000](http://localhost:3000). Оформление — тёплое,
редакторское, в духе журнала Kinfolk: кремовый фон, книжная антиква (шрифт Lora через
`next/font/google`), приглушённый терракотовый акцент вместо ярко-синего. Намеренно
единственная светлая тема, без переключения под системную тёмную (см. `globals.css`).

Лента — один столбец: картинка сверху во всю ширину (`max-height: 320px`,
`object-fit: cover`), текст под ней. Пробовали портретную рамку с `object-fit: contain`
(без обрезки) — но на landscape пресс-фото изданий это давало много пустых полей
сверху/снизу, поэтому вернулись к обычному `cover`-кропу. Без рамок и фона у самой
карточки — разделение между карточками просто отступ.

Над лентой — витрина будущего фильтра по изданиям (`ВСЕ ИСТОЧНИКИ ▾` + строка с
перечислением, как на страницах категорий Kinfolk) — пока не кликабельно, просто
задел под реальную фильтрацию, когда до неё дойдут руки.

Каждая карточка — это один инфоповод (`cluster_id`, см. ниже): сверху лого издания +
название (ссылка на оригинал) + дата, затем текст саммари. Если новость подхватили
несколько изданий (или то же самое издание дважды) — рядом появляется "+N источника",
а все они перечислены в модалке. Клик по тексту открывает модальное окно
(`ArticleModal.tsx`) снизу экрана (bottom sheet, как в iOS) с более подробным
пересказом (`ai_summary_long` — не перевод оригинала, самостоятельный, но более полный
пересказ своими словами) и списком источников со ссылками на оригиналы — это
единственный способ перейти к первоисточнику из модалки (отдельной кнопки "Читать
оригинал" нет). Данные читаются из той же БД через `src/lib/feed.ts`, который также
отдаётся как JSON по `GET /api/feed` (готово для мобильного клиента или другого
потребителя в будущем).

Страница и API-роут читают `src/lib/*.ts` напрямую (импорты с `.js`, как того требует
`tsx` для CLI-скриптов) — webpack настроен резолвить это через `extensionAlias` в
`next.config.mjs`.

**Грабли со styled-jsx:** в SWC-варианте styled-jsx (используется в Next.js по
умолчанию) есть баг — он не добавляет свой scope-класс на КОРНЕВОЙ элемент,
возвращаемый компонентом (только на вложенные), из-за чего CSS-правила для этого
элемента просто не совпадают с ним в рантайме — даже с полностью статичным
`className`. Проявлялось это как модальное окно, "залипшее" за нижним краем экрана:
`position: fixed` из `<style jsx>` не применялся к корневому `<div>` overlay. Обходится
заданием критичных/переключаемых стилей корневого элемента через `style={{...}}`
напрямую, а не через `<style jsx>` — см. `ArticleModal.tsx`.

### 7. Картинки и контекст для саммари (best-effort)

Пайплайн пытается подтянуть с страницы каждой статьи (`src/lib/ogTags.ts`):
- `og:image` — картинка для карточки;
- `og:description` — обычно просто маркетинговый тизер без фактов (см. калибровку
  ниже), полезен как запасной вариант;
- **текст самой статьи** — этим кормим AI-саммаризацию, чтобы получить реальные факты,
  а не голый заголовок. Приоритет извлечения:
  1. **JSON-LD `articleBody`** (schema.org-разметка) — если есть, самый чистый
     источник: полный текст без единого тега и навигационного мусора. Есть у Wired,
     The New Yorker, The Verge (похоже, общий шаблон Condé Nast/Vox Media).
  2. **Фильтрованные `<p>`-абзацы** — запасной вариант для TIME/WaPo/NYMag, где
     JSON-LD нет. Отсеивает явный мусор (меню, "Subscribe", заглушки комментариев)
     эвристикой по плотности пробелов, но не идеален — на сложных шаблонах (напр.
     NYMag) реальный текст может идти после солидного куска мусора.

**Важно:** NYT (Cloudflare JS-челлендж) и Telegraph (собственная anti-bot защита)
активно блокируют такие запросы — для них остаётся только сниппет из RSS, без картинки
и без текста статьи. Осознанно не пытаемся обходить эту защиту (JS-рендеринг/
headless-браузер) — это уже противодействие мерам издания, а не чтение публичных данных.

**Защита от мусора на входе саммаризации:** если контекст оказался нечитаемым (навигация
сайта, пустые заглушки, подпись к комиксу без текста), промпт просит модель ответить
служебным токеном `NO_CONTENT` вместо того, чтобы придумывать факты или писать
по-русски "текст отсутствует, пришлите материал" (было — и это сохранялось в базу как
видимое пользователю саммари, реальный баг на практике: у части статей New York
Magazine эвристика вытащила только навигационное меню, и модель написала отказ вместо
саммари). При `NO_CONTENT` код автоматически откатывается на более простой источник
контекста (`summarizeWithFallback` в `src/lib/summarizer.ts`); если и заголовок/RSS-
сниппет не помогают — в последнюю очередь просто использует заголовок статьи как есть.

Для статей, собранных до появления этих фич:
- `npm run backfill-og` — картинка/описание (best-effort, пропускает заблокированные источники).
- `QUALITY_LIMIT=N npm run upgrade-quality` — пересчёт саммари для N последних статей
  (по умолчанию 50) с полным текстом статьи вместо голого тизера; заодно обновляет
  `embedding` (он считается от текста саммари). Кластеризацию (`cluster_id`) не
  трогает — пересчитывать её задним числом отдельная, более рискованная задача.

### 8. Группировка: только одинаковые новости, без "тредов"

Была попытка сделать более широкую группировку `topic_id` — связанные, но не
идентичные статьи на одну тему (порог мягче, источник любой), показывалась одной
карточкой-тредом из нескольких абзацев. Убрали: на практике мягкий порог регулярно
склеивал в один тред реально разные новости на смежную тему (например, новость про
инвестиции Гейтса в ИИ и отдельную новость про тревогу вокруг регулирования ИИ) —
не то, что ожидаешь от ленты. Единственный уровень группировки теперь — `cluster_id`
(тот же инфоповод, строгий порог `DEDUPE_THRESHOLD`), источник при этом может быть
любым, включая тот же самый (см. `src/jobs/fetchAndProcess.ts`).

**Важно про инкрементальность:** группировка ищет совпадение только среди уже
существующих на момент вставки статей (`id < newId`, см. `src/lib/grouping.ts`) —
иначе жадное сопоставление с "ближайшим соседом" рвёт естественно единую группу на
осколки (так и произошло при бэкфилле `topic_id`, пока эта группировка ещё
существовала: 5-серийный подкаст The New Yorker "The Journey" распался на 3 разные
группы, потому что каждая статья тянулась к своему ближайшему соседу вместо
транзитивного объединения всех пяти). В живом инкрементальном пайплайне это не
проблема (будущих строк ещё не существует на момент вставки), но при бэкфилле по уже
собранным данным — критично.

## Заметки по калибровке (по реальным данным)

- `DEDUPE_THRESHOLD=0.75` — откалибровано на реальном прогоне: одна и та же новость
  (Supreme Court/mail-in voting) из двух разных изданий дала косинусную похожесть
  **0.769**, а ближайшая пара разных новостей — **0.64**. Порог 0.75 разделяет их
  с запасом. Если добавятся источники с другим стилем саммари — стоит перепроверить.
- В `db/schema.sql` намеренно нет `ivfflat`/`hnsw`-индекса на `embedding` — при
  малом объёме данных (retention в днях) approximate-индекс с непродуманными
  `lists`/`probes` либо не даёт выигрыша, либо (как было на практике: 100 lists
  на пустой таблице) почти всегда промахивается мимо реальных дублей. Точный
  скан здесь надёжнее. Возвращаться к approximate-индексу имеет смысл только
  при кардинально большем объёме строк.
- Саммари иногда обрывались на середине предложения — упирались в
  `maxOutputTokens`/`max_tokens` (было 150/120, стало 300). Плюс защита в коде
  (`ensureCompleteSentence` в `src/lib/prompt.ts`): если ответ всё равно обрежется,
  подрезаем до последнего целого предложения, а не оставляем висящий обрывок.
  `npm run resummarize` — пересчитать саммари для уже сохранённых обрывков.
- Лента сортируется по времени публикации (`latest DESC`), а не по числу
  источников — иначе склеенные новости "залипали" наверху ленты независимо от
  свежести, что не соответствует идее ленты в стиле Twitter.
- Целевая длина саммари — 300-350 символов, 2-3 предложения (было 200/1-2, потом
  пробовали 400-500 — оказалось многовато). Промпт также просит не перечислять все
  однородные второстепенные детали (например, все вовлечённые ведомства/организации),
  а называть максимум одну-две — иначе саммари раздувается за счёт менее важного.

## Источники

Список и RSS-ссылки — `src/config/sources.ts`. Сейчас 8: The New York Times (World),
The Washington Post (National), Wired, The Telegraph, The Verge, TIME, The New Yorker,
New York Magazine (только раздел Intelligencer — у nymag.com нет общего RSS на весь
сайт). **The Verge, TIME, The New Yorker и New York Magazine не блокируют og-теги** —
у них есть и картинка, и полное описание; NYT и Telegraph по-прежнему блокируют (см.
раздел про og-теги выше).

National Geographic не подключён — официального публичного RSS не нашлось (проверено
~15 вариантов путей, везде 404 или недоступный домен). Если найдёшь рабочую ссылку —
добавляй в `src/config/sources.ts` и `db/init` сам, либо попроси заново проверить.
